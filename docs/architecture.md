# 架构评审：个人 Mac 课程工具

评审日期：2026-10-04。下文保留当时 0.6.6 的源码、测试、打包配置及安装版评审证据；没有审阅用户凭据、课程正文或线上账号数据。

2026-10-06 更新：当前源码已到 0.6.10，桌面任务简化为两种，新增 eLearning 个人配置编辑，密码与 API Key 改为本地文件保存。下文有关每次保存创建 Keychain profile、版本号未更新的描述仅对应历史状态；安装互斥、子进程凭据环境及状态迁移建议仍应结合当前代码评估。现行行为见[开发文档](development.md)。

## 结论

**对单用户、手动启动、少量课程的 Mac 桌面工具，整体架构合理，可以继续在现有结构上维护。** UI 通过子进程调用业务代码，耗时网络不阻塞主窗口；产物校验、独立索引、有限重试和取消均已有测试。下一步应优先改善更新过程、状态兼容和模块边界，保持现有功能与文件保留规则。

当前更适合本机使用；多人部署、无人值守运行、自动调度、大规模课程同步不是已验证的能力。下述建议均为后续改进，未在本次进行大规模重构或启用后台任务。

## 已成立的设计选择

| 选择 | 代码证据 | 实际价值与边界 |
|---|---|---|
| GUI 与耗时执行分进程 | [mac_gui.py](../src/mac_gui.py) 的 `launch()`；[engine.py](../src/engine.py)；[elearning_panel.py](../src/elearning_panel.py) 的 `launch()` | 可停止网络/转录任务；录像有进程组清理，eLearning 单 worker 取消；同一窗口限制操作并发 |
| iCourse 与 eLearning 只共用 IDP 协议 | [fudan_idp.py](../src/fudan_idp.py)、[webvpn.py](../src/webvpn.py)、[auth.py](../src/elearning_helper/auth.py) | 两套服务回调、会话和成功校验独立，避免复用错误的登录状态 |
| 两类下载保留不同策略 | [video_download.py](../src/video_download.py)；[sync.py](../src/elearning_helper/sync.py) 的 `download_complete()`、`publish_without_overwrite()` | 大录像保留安全断点并校验后替换；小课件完整重试且永不覆盖同名文件。两者职责有实际差异 |
| 状态与用户产物分层 | [pipeline_state.py](../src/pipeline_state.py)、[artifacts.py](../src/artifacts.py)、[state.py](../src/elearning_helper/state.py) | 产物可校验复用，失败不会把未完成内容当作成功；课程文件、队列和提醒不混入一个数据库 |
| 进度模型包含身份与顺序 | [task_events.py](../src/task_events.py)、[task_view_model.py](../src/task_view_model.py) | 以运行 ID、序号、课程/课次组合隔离事件，多课次并行阶段显示有明确依据 |
| 同名保留优先于远端身份判定 | [sync.py](../src/elearning_helper/sync.py) 的 `same_name_file()`、`name_preserved()`、`sync_file()` | 同名常规文件直接零传输跳过，不计算内容散列、不推进已验证索引；本地批注得到保护 |

同名策略有明确取舍：老师上传同名新版本时不会自动取回；“同名保留”也不证明本地完整或内容一致。下载期间用户才创建同名文件时，程序已经发生的传输不能撤销，但最终仍保留用户文件、不另存、不写假散列。测试覆盖这两种竞争窗口。

## 优先改进项

优先级含义：P1 为下一次正式升级/分发前应优先处理的完整性问题；P2 为后续维护迭代，不阻止当前手动使用。

### 1. P1：把更新保护与版本可追溯性纳入安装器

证据：[install_mac_runtime.py](../scripts/install_mac_runtime.py) 的 `main()` 只获取 `pipeline.lock`；`install()` 原地执行依赖同步和 wheel 重装，没有检查 eLearning 的 `run.lock` 或仍打开的原生 App。内部函数直接调用还依赖调用方持锁。`pyproject.toml` 仍为 `0.6.6`，同一版本号下已有多轮本地功能修订。

影响：用户仅运行 eLearning 或保留空闲 App 时仍可能更新其运行环境；更新中途失败缺少整体回退，版本号不足以确认实际安装了哪一轮修订。

建议：安装器统一检查 App 与两类执行锁，把校验过的新 runtime 暂存后切换并保留可回退版本；增加源码/构建标识并纳入自检。发布副本还应替换 `src/elearning_helper/config.json` 中的个人路径和课程映射；当前 wheel 特例会携带它，虽不含密码也并非通用配置。

当前措施：本次安装在外层检查了原生 App 进程和两类任务锁，已安全完成；仓库自带安装器尚未内建这些额外检查。日常更新须先结束任务并退出 App，不能只依赖安装器自动拒绝。

### 2. P1：明确状态版本与文件/索引恢复协议

证据：[pipeline_state.py](../src/pipeline_state.py) 与 [eLearning state.py](../src/elearning_helper/state.py) 使用建表语句初始化，尚无统一版本迁移流程；`sync_file()` 先原子链接发布文件，再调用 `save_file()` 写 SQLite。文件系统与数据库不能一起提交。

影响：崩溃后可能出现已发布但未索引的文件；当前同名策略会安全保留它，但其来源校验状态仍未确认。未来表结构变化可能使旧状态无法读取；直接删除数据库会丢失作业基线和未读提醒。

建议：为两套 SQLite 分别引入版本号与可回退迁移测试；定义发布前后故障的恢复记录，并继续区分“同名保留”“已验证同内容”。增加发布后写库失败、旧数据库升级、取消时提交的故障注入测试。恢复机制不能自行把同名文件标为远端散列相同，也不能违背不覆盖政策。

### 3. P2：收窄子进程凭据范围并完善生命周期

证据：[preferences.py](../src/preferences.py) 的 `runtime_environment()` 向录像引擎环境传递 UIS、语音和笔记凭据；[asr/client.py](../src/asr/client.py) 的 `CloudWorker._start()` 未显式缩减继承环境。eLearning 新凭据已通过 stdin 提交。`Preferences.save()` 每次创建新 Keychain profile，提交后没有旧 profile 清理流程。

影响：录像子进程及其后代可能继承当前任务不需要的凭据；长期重复保存会积累旧 Keychain 条目。这是缩小暴露面和维护成本的问题，未发现本次测试把真实密钥写入日志的证据。

建议：为每种任务构造最小启动环境，将必要秘密通过专用请求传递，使用虚构值断言不相关子进程不继承；建立成功提交后的受控旧 profile 回收方案。保留用户现有保存和自动恢复选择，不新增重复许可弹窗，不在本次迁移或清理真实凭据。

### 4. P2：逐步拆分编排与展示，统一结果契约

证据：[pipeline.py](../src/pipeline.py) 约 1,757 行，包含参数、规划、迁移、队列、工作线程和进度逻辑，并使用模块级 `_STATE`。`ElearningPanel.apply_payload()` 从 CLI `__main__` 导入 `display()` 并重定向 stdout；整个 JSON 等到进程结束后解析，结果字典未版本化。独立 eLearning 启动脚本没有主窗口凭据提供器。

影响：改变日志文字或 CLI 展示会影响 GUI；结果增大时缓冲和错误定位困难，旧入口容易让用户误以为登录功能失效。跨界面复用代码的维护成本继续增长。

建议：先提取纯结果 DTO/格式化层与任务启动服务，再逐步拆出录像计划器和各阶段执行器；为 eLearning 增加版本化结果/事件协议，统一正式入口并明确测试入口。下载器保留各自语义，可共享诊断、取消和状态契约。按有回归证据的小步变更推进。

### 5. P2：为真实环境与发布身份建立最小验收记录

证据：`tests/` 通过临时文件、模拟 HTTP 和 offscreen Qt 覆盖大量分支；[mac_app_check.py](../src/mac_app_check.py) 使用默认设置做自检。[CI 配置](../.github/workflows/ci.yml) 定义多平台矩阵，但本次没有查询远端运行结果。真实 TCC 授权、学校权限变化和服务商响应无法由 fixture 完整替代。

影响：480 项通过能说明已覆盖行为未回归，不能承诺学校或服务商接口将一直不变，也不能证明每次重装后系统权限都保留。

建议：每次发布记录构建标识、操作系统、安装/重开、目录授权、用户主动登录、一个小文件和一段短音频的验收结果；真实账号和付费调用由用户明确手动发起。扩展离线测试优先覆盖接口形状变化、分页中断、锁冲突和崩溃恢复，不为提高数量重复实现细节。
