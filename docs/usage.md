# 使用说明

当前桌面操作均由用户手动发起；打开 App 不会自动检查课程或作业，没有启用后台轮询、邮件或系统推送。[安装与更新](mac-install.md) · [eLearning 完整规则](elearning.md) · [故障恢复](troubleshooting.md)

## 桌面任务

| 本次任务 | 用途 | 需要学校账号 | 需要笔记 API |
|---|---|---|---|
| 下载录像并生成笔记 | 补齐录像和笔记；复用已有转录，必要时云端转录 | 是 | 是 |
| 只下载录像 | 仅补齐录像，不调用语音和笔记服务 | 是 | 否 |

桌面只提供这两种任务，通过课程 ID 和课次 ID 找到资料。完整模式可能产生语音和笔记服务费用；已有完整笔记会保留，不因模型变化重做旧课。[设置语音服务](cloud-asr.md)。

### 课程 ID 和课次 ID

先在 [iCourse 网页](https://icourse.fudan.edu.cn)打开自己有权访问的课程，查看课程页面地址中的课程编号。网页课程和课程中的单节回放各有自己的编号，不能混填。

- “课程 ID”：一个课程或多个课程，使用英文逗号，例如 `12345,23456`。
- “指定课次”：单节回放的编号，例如 `123456`；留空表示处理所选课程的全部可用回放。
- “排除时段”：可留空。例 `12345:星期一早上,evening`，排除这门课相应时段。

第一次先处理一个课次。后续再次启动同一任务，会复用已经完成并验证的产物。网页尚未发布回放时会记录“暂无”，下次运行再检查。

### 保存与补齐

所有输入统一放在「设置」：学校账号、录像与笔记、eLearning、语音与笔记服务、高级与检查。修改后点击「保存设置」，两组功能的新任务才使用这些值。未保存时顶部有提示，新的开始/刷新/同步暂不可用；运行中的任务和停止按钮不受影响。保存使用同一个本地文件，校验或写入失败时保留原配置。

“下载录像并生成笔记”按缺项处理：

- 没有录像：下载并校验录像；已有笔记则保留，否则继续补笔记。
- 有录像、没有笔记：有可复用转录就直接生成笔记，否则转录后生成。
- 录像和笔记都已有：使用已有结果，不重复调用模型。
- 录像已被标记异常：提示先完整校验或重新下载，避免把异常文件交给云服务。

已有笔记允许保留用户修改，移动课程目录不会仅因旧来源路径消失就自动重做。复用转录时使用当前录像核对已有来源摘要。新转录仅在服务提供真实时间戳时生成字幕；已有转录/笔记不会为了补字幕而被自动重新识别。

桌面不再提供强制重做复选框。高级命令行仍保留 `run --mode summarize --redo-notes`（只重做笔记）、`--overwrite`（重新转录及生成笔记）和 `transcribe` 单文件入口；这些操作可能产生费用，应明确指定课程/课次及路径。不要为了普通补齐删除已有产物。

### 查看多门课程的进度

「录像与笔记」页只显示本次配置摘要、任务进度与操作。课程名称可以展开，每个课次分别显示“下载 / 云端转录 / 笔记”。一节课下载、另一节课转录、第三节课等待笔记时，各自的状态同时保留。阶段仍各只有一个工作线程，不会因课程多而增加同时调用笔记 API 的数量。

工作页不放输入框；录像页点击「调整设置」、eLearning 页点击「前往设置」修改课程及保存位置。相同的录像和笔记目录只显示一次，长路径省略显示，悬停可查看完整路径。运行中，摘要固定显示本次使用的配置；结束后显示下次运行配置。「更多操作」集中放置失败重试、完整校验、指定录像重下载和日志显示，日志默认收起。

- 顶部“本次已结束 X/N 课”包含成功、失败、等待回放和停止的课次；旁边的成功数单独统计。“使用已有”表示复用已有产物。
- 下载百分比来自接收字节；转录百分比来自已完成音频块，块处理期间可能暂时不变。
- 笔记没有可可靠测量的百分比，显示已用时间。选中该课次可看模型、请求次数、完整原文字数和重试等待。后台心跳只说明程序能响应，不代表模型已生成多少内容。
- “所有课次记录 / 所选课次记录”可切换关键日志。向上阅读时不会强制滚到底部；点击“回到最新”恢复跟随。计时刷新不追加日志。
- 「更多操作 → 显示诊断详情」提供底层输出；出现问题可在同一菜单“复制问题摘要”或“导出诊断”。任务日志位于 `~/Library/Logs/Fudan iCourse Subscriber/tasks.log`，每份约 2 MB，最多五份，开始任务时清理七天前的旧日志。启动日志 `application.log` 在重开 App 时达到 2 MB 会保留一份旧副本。
- 「更多操作 → 上次运行结果」查看最近一次运行摘要。它是历史记录，不表示后台仍在工作；App 异常退出时不会把未结束任务显示为成功。

部分课次失败时，先查看对应行的原因，需要调整模型或账号可前往设置并保存。然后在「更多操作」点“仅重试失败课次”：沿用上次的输入和保存位置，仅处理失败的课程 / 课次组合，并复用此前成功保存的文件。笔记请求失败后重试可能再次调用 API；若完整响应已经缓存，则优先复用。成功课次不会再次处理。

如果提示“录像未下载完整”或“提取出的音频不完整”，故障发生在本地读取录像阶段，还未上传本次音频，与语音 API Key 无关。文件头可能写着完整课时，但实际视频只保存了一部分，所以播放器显示的总时长不能证明下载完整。

- 0.6.3 起会检查 MP4 数据块是否超出文件结尾；已被旧版标为完成的残缺 MP4 也不会继续复用。此检查只读取少量文件头，不会逐帧扫描所有课程，也不能替代完整解码检查。
- 优先按 32 MiB 请求录像；服务器提供可靠文件标识时，下载中断会保留断点。0.6.7 起续传先按接收摘要回读已有分段，显示“继续下载 · 已校验 … MB”。服务器文件变化时重新下载；不支持安全续传的服务使用完整下载。
- 视频及 `.download.part` 始终写入选定的保存位置，支持直接写外置盘，不使用内置盘中转完整录像。系统盘仅保存小型接收摘要（Mac 默认 `~/Library/Application Support/Fudan iCourse/download-checks/`），外置盘 `.icourse` 保留镜像记录；成功后清理断点。摘要不含签名链接或登录凭据。
- 每个写入分段回读比较 SHA-256，下载结束再次完整回读并检查媒体，然后才替换正式录像。macOS 尝试更强刷盘及禁用读取缓存；设备不支持时退回普通同步，不能保证故障硬件正确保存数据。此过程只使用固定大小内存缓冲；额外磁盘读取会增加完成时间。
- 旧版没有接收摘要的断点不能直接信任，新任务会提示并重新下载。新格式断点若有未提交尾部，核对已提交分段后仅丢弃未提交部分；不使用文件大小或时间戳代替内容比较。
- 网络失败可用“仅重试失败课次”续传。出现写入或回读不一致，会保留现场并暂停本轮后续下载；检查保存位置后，填写课程 ID 和指定课次，点击“重新下载指定录像…”。该入口只下载并替换所选录像，保留原文、笔记，不调用云服务；重复文件和符号链接仍需先处理。
- 已有录像被校验记录阻止时，“仅重试失败课次”的下载阶段也可重新下载该录像，并保留已有文字。下载数据与回读一致但媒体本身不合法时，仅终止该课，保留临时录像及脱敏原因，不在本轮重复整课下载。
- 旧录像会保留到替代文件通过检查后再被替换，不需要先删除整个课程目录。如果重新下载仍失败，请检查学校网页回放能否播放至结尾，并检查网络和外置盘连接；仅凭此错误无法确定是服务器、传输还是存储出了问题。

“停止录像任务”会先显示停止中，待后台清理后恢复开始按钮。已经保存的结果继续保留；下次正常开始时会检查并复用。停止不等于暂停正在进行的 API 请求，也不保证服务商停止计费。

### 笔记生成规则

音频在本地提取、压缩后按块上传语音服务，减少内存占用。识别结果合并为整课原文后，笔记模型只收到一次完整请求。这两种“分段”不是同一个阶段。

正常成功路径：完整原文 → 一次模型请求 → 一份 Markdown 笔记。没有提纲、逐章写作、AI 核对或自动修订轮次。标题与段落由模型正常排版。

默认单次输出上限为 65536 tokens、请求等待上限为 20 分钟。输出上限是允许生成的预算，不是目标字数；实际消耗以服务商记录为准。模型需同时容纳完整输入和预留输出。

设置中的“恢复笔记推荐参数”可恢复上述预算。已完成笔记可以自行编辑，普通运行会保留这些修改；主动选择重新生成时，旧笔记仍先归档。

- 服务临时故障或空正文：有限重试，等待 5 秒、15 秒，每个模型最多 3 次尝试；配置了备用模型时可能继续尝试备用模型。
- 输出达到长度上限或异常结束：报错，不保存半篇正式笔记；不会自动拆分成更多请求。
- 最后保存文件失败：完整响应已写入隐藏缓存时，相同输入和配置重试可直接保存，避免重复付费。
- 重新生成成功：同名旧笔记存入隐藏历史目录，当前正式笔记仍只有一份。

## eLearning 文件与作业

1. 从 `~/Applications/iCourse.app` 打开主窗口，在「设置 → 学校账号」填写学号和 UIS 密码。只使用 eLearning 无需语音或笔记 API Key。
2. 在「设置 → eLearning」修改保存根目录与课程表；同步记录位置及文件大小上限在「高级与检查」。点击「保存设置」，重启仍保留；修改目录不会自动搬移已有文件。
3. 打开「eLearning 与作业」，点击「刷新作业」或「同步文件」。点击即使用已保存的账号登录，没有额外许可对话框；空账号/密码会在页面内提示。
4. 「刷新作业」只读取作业并更新基线；「同步文件」还会处理课程设置中列出的课程文件。课程范围来自独立的 eLearning 课程设置，不跟随录像设置中的课程 ID 自动变化；eLearning ID 与 iCourse ID 不同。
5. 查看课程分组、北京时间截止日期、当前学生提交状态，或点击学校入口。详细日志默认折叠，配置统一在设置页维护。读取失败不等于没有作业。

所有可访问文件类型均可保存，单文件必须严格小于 **50,000,000 字节**，未知大小或等于上限也跳过；文件不会自动运行、解压或打开。默认只写每课的 `课件/`，不扫描旧 `CLOUD/`、`课程ppt/`、`资料/`。

**同名普通文件直接保留**：规范化后同名即跳过，不下载、不比对、不覆盖、不另存，即使老师更新同名内容也如此。同名比对复选框已取消；跳过结果不代表远端内容相同，不虚写远端 SHA-256。若希望查看老师同名新版本，请自行在学校页面查看或另行保存到自己选择的位置，当前自动同步规则仍保留原文件。

异名文件继续按内容散列去重：有可验证索引时可零传输复用，否则可能先临时下载再确认重复。「同名保留」「重复跳过」「保留本地变化」均不是下载失败；日志会区分是否实际发生传输。

锁定作业在所有筛选及普通日志中隐藏，已提交的锁定项也隐藏，不计数、不显示空课程组。底层已获取元数据和基线保留，解锁后手动刷新可再显示。首次成功检查建立基线；以后每次手动运行检测新增作业及截止日期变更，没有临近截止时的自动推送。提交状态来自学校接口，未知状态或无需在线提交不推定为完成。

本地未读提醒可用以下命令查看；第二条仅在本地标记已读：

```sh
.venv/bin/python -m src.elearning_helper alerts
.venv/bin/python -m src.elearning_helper ack 1 2
```

原始提醒列表可能包含锁定作业元数据，界面过滤不会删除历史。CLI 的在线 `sync/check` 默认需独立的运行时 Bearer 认证，不能自动读取 GUI 设置；日常账号密码登录请从主窗口发起。离线检查可运行：

```sh
.venv/bin/python -m src.elearning_helper demo
.venv/bin/python -m src.elearning_helper doctor
```

`demo` 只在临时目录模拟，`doctor` 只检查配置和路径，两者都不验证学校登录。在线 `sync --dry-run` 会访问学校清单，但不下载、不写索引或提醒，不能称为离线检查。配置与退出码见 [eLearning 文档](elearning.md)。独立 eLearning 启动脚本仅供界面测试，不提供统一设置凭据。

### 停止、重试和运行互斥

录像与 eLearning 可以同时运行，各自有独立状态和停止按钮；同一功能仍不能重复启动。运行期间可以修改并保存设置，当前任务保持启动时的配置，新任务使用最新保存值。关闭窗口会同时停止两边并等待清理结束。

同一个课程根目录下的 `录屏/`、`笔记/`、`课件/` 可并行使用；若把 eLearning 指向整门课程目录或录像/文字输出子目录，主窗口会阻止重叠任务并提示修改保存范围。录像跨进程使用 `pipeline.lock`，eLearning 使用自己的 `run.lock`；这些锁不提供跨工具的全局互斥，另开的 CLI 仍应避免同时操作相同输出位置。

点击「停止」后等待界面结束；成功文件和已经提交的基线保留，下次手动运行继续检查。短读或正文读取中断对该失败文件最多从头尝试 3 次，间隔 1 秒、2 秒，不发 Range；录像续传是另一套策略。认证失败、大小不符、本地写入错误需先排查，不能靠无限重试解决。

不要通过删除课程目录或数据库来重试。强制结束可能留下隐藏 `.elearning-*.part`，它不是完成文件；程序正常异常会清理本次临时文件，但不自动删除其他运行留下的文件。发布成功而索引尚未提交时崩溃，下次仍按同名保留，不伪造已验证状态。

## 文件结构

假设课程保存位置是 `/Volumes/CourseDisk/iCourse`，笔记保存位置是 `~/Documents/Study/courses`：

```text
/Volumes/CourseDisk/iCourse/
└── 12345-课程名称/
    └── 录屏/
        ├── 课次标题_123456.mp4
        ├── 课次标题_123456.srt     # 仅在服务返回完整真实时间戳时
        └── .icourse/                  # 内部校验资料

~/Documents/Study/courses/
└── 12345-课程名称/
    ├── 笔记/
    │   ├── 课次标题_123456.md          # 阅读这一份笔记
    │   └── .icourse/                  # 缓存与历史
    ├── 课件/                         # eLearning 映射到此课程时
    │   └── 讲义.pdf
    └── 原始txt/
        ├── 课次标题_123456.txt
        └── .icourse/                  # 转录时间轴等
```

目录名以实际程序输出为准。只下载模式不生成字幕；仅在语音接口返回完整时间戳时才生成字幕。单文件转录直接在指定输出目录生成 TXT 和可用的 SRT，内部时间轴和校验记录也在隐藏 `.icourse` 中。

Finder 默认不显示 `.icourse`。按 **Command+Shift+.** 可切换隐藏文件。内部 JSON 用于校验与恢复，不要为“清理参数”而批量删除。

## 命令行

以下在源码目录运行，且已执行安装器。命令行与 App 共用同一套转录、流水线和整课总结代码；源码修改后要重新安装才能更新 App。

```sh
# 本机环境检查，不登录、不调用笔记 API
.venv/bin/python -m src.cli doctor

# 检查当前语音协议的连接，不上传音频（凭据来自环境变量）
.venv/bin/python -m src.cli check-asr

# 转录自己的单个本地文件
.venv/bin/python -m src.cli transcribe /path/to/lecture.mp4 --output-dir /path/to/results

# 更换兼容的服务和模型；ASR_API_KEY 也需使用该服务的密钥
.venv/bin/python -m src.cli transcribe /path/to/lecture.mp4 \
  --base-url https://api.example.com/v1 --model your-speech-model
```

课程流水线使用环境变量或 `.env`；单文件转录和连接检查默认只读环境变量，也可显式添加 `--env-file .env`。命令行不会自动读取 GUI 的本地设置文件。先创建自己的配置文件：

```sh
cp .env.example .env
chmod 600 .env
```

用文本编辑器修改 `.env`，填自己的账号和 API Key。不要将 `.env` 上传或分享；外部已经导出的同名环境变量优先于 `.env`。

```sh
# 仅查询可用回放，会登录学校
.venv/bin/python -m src.cli run --env-file .env --mode download --course-ids 12345 --list-only

# 下载并生成笔记；路径中的磁盘名替换成自己的
.venv/bin/python -m src.cli run --env-file .env \
  --mode download_and_summarize --course-ids 12345 --sub-ids 123456 \
  --out-dir /Volumes/CourseDisk/iCourse --summary-dir "$HOME/Documents/Study/courses"

# 复用本地转录，仅重写笔记
.venv/bin/python -m src.cli run --env-file .env \
  --mode summarize --course-ids 12345 --sub-ids 123456 --redo-notes \
  --out-dir /Volumes/CourseDisk/iCourse --summary-dir "$HOME/Documents/Study/courses"

# 查看全部参数
.venv/bin/python -m src.cli run --help
```

### 常用环境变量

| 变量 | 用途 |
|---|---|
| `StuId`、`UISPsw` | 学号、UIS 密码，注意大小写 |
| `COURSE_IDS` | 英文逗号分隔的课程 ID |
| `DOWNLOAD_DIR`、`SUMMARY_DIR` | 视频和文字的两个根目录 |
| `LLM_NAME_1`、`LLM_BASE_URL_1`、`LLM_MODELS_1`、`LLM_API_KEY_1` | 模型服务名称、基础地址、模型 ID、密钥 |
| `LLM_API_STYLE_1` | 可选 `openai` 或 `anthropic`，通常自动识别 |
| `LLM_MAX_OUTPUT_TOKENS` | 单次输出预算，默认 65536 |
| `API_TIMEOUT_MS` | 单次请求等待上限，毫秒；默认 1200000 |
| `ASR_PROVIDER` | `openai`（默认兼容接口）或 `dashscope`（百炼录音文件识别） |
| `ASR_BASE_URL`、`ASR_MODEL`、`ASR_API_KEY` | 可配置的语音基础地址、完整模型 ID、所选服务的密钥；没有模型白名单，但模型必须支持所选接口协议 |
| `ASR_TIMESTAMP_ALIGNMENT` | 仅百炼录音接口：`default`（默认不传）、`enabled`、`disabled`；开启前确认模型支持 |
| `ASR_LANGUAGE`、`ASR_INITIAL_PROMPT` | 可选语言和术语提示；不支持的服务请留空 |
| `ASR_RESPONSE_FORMAT` | 默认留空；可选 json、verbose_json、text、srt，须服务支持 |
| `ASR_CHUNK_SECONDS` | 上传音频块最长时长，默认 300 秒，范围 30–1800 |
| `ASR_MAX_UPLOAD_MB` | 单块文件上限，默认 20 MB；程序会据此进一步缩短块 |
| `ASR_TIMEOUT_SECONDS`、`ASR_RETRIES` | 默认 300 秒、最多重试 2 次；百炼等待超时保留任务，下次继续查询，不自动重复提交 |
| `FFMPEG_DIR` | 自定义 ffmpeg/ffprobe 的目录 |

旧变量 `LLM_INPUT_CHAR_LIMIT` 已停用；笔记输入不再按字符切块。旧本地转录参数不再使用。

退出码：`0` 为没有失败任务，`1` 为处理失败，`2` 为已有另一条课程流水线正在运行。已完成目标会复用；取消后重跑会检查产物。云端转录会复用成功的音频块。

## 数据与备份边界

课程文件是用户产物；隐藏 `.icourse` 和 ASR 缓存决定能否直接复用或恢复；SQLite 分别记录录像阶段和 eLearning 文件/作业状态。设置、密码和 API Key 在同一个本地文件中，日志独立保存，路径见[安装指南](mac-install.md#文件安装在哪里)。备份时应在两类任务都停止后进行，数据库若有 `-wal`/`-shm` 文件需与主库一致保存，不能在任务运行时只复制一个 SQLite 文件。不要共享含个人课程、路径或凭据的备份。

录像流程有已知旧产物布局迁移及笔记归档；eLearning 不移动、删除或覆盖既有课件，两者保留语义不同。

桌面版不会自动发送邮件。`main.py`、数据库和邮件脚本保留作旧接口兼容用途，不属于这里的标准使用流程。

## 已有录像快速跳过与手动完整校验

两种任务都按课程目录和完整课次 ID 查找正式 `.mp4`。“只下载录像”找到已有正常文件时显示 **已有，未校验／跳过**，不读取整段视频或调用云服务。“下载录像并生成笔记”复用已有录像并补齐缺少的笔记；录像与笔记齐全时显示“使用已有”，计入完成。复用不代表本次重新做过录像完整校验。旧版带课次 ID 的文件名仍支持，不移动原文件。

这能避免外置盘重挂载后读取整学期旧录像，但文件名相同不代表内容完整。空文件、符号链接、重复课次文件、损坏的校验记录、明确失败/待核对标记及已记录的媒体验证失败均不会被当作正常跳过。仅剩 `.download.part` 的课次仍视为缺少正式录像；规划不会清理它，只有用户开始该课次的实际下载才进入原有断点处理。

需要检查时，在「设置 → 录像与笔记」选定课程 ID（可填写“指定课次”缩小范围）并保存，再在「录像与笔记 → 更多操作」点击 **完整校验录像…**。它只读完整视频，检查已知 SHA-256 和媒体结构，并在本机保存验证结果；不登录、不下载、不调用云服务。过程中显示字节进度，可点击“停止录像任务”；取消不会把未完成项目记为通过，也不会清除原有失败记录。校验与课程任务互斥。

CLI 对应入口：

```bash
python -m src.cli verify-videos --out-dir "$HOME/iCourse/课程" --course-ids 12345 --sub-ids 123456
```

完整校验不逐帧解码，不能保证每一帧的视觉内容正确。它同时检查本机保存的接收摘要及可读的外置校验记录；失败不会丢弃原接收摘要。损坏的外置记录不能仅凭文件大小和时间戳解除阻止；显式完整校验通过，或重新下载并通过验证后才能恢复。校验不覆盖或删除原视频及其旧校验文件。

需重新取得指定录像时可点“重新下载指定录像…”，或运行：

```sh
python -m src.cli run --mode download --course-ids 12345 --sub-ids 123456 \
  --out-dir /Volumes/CourseDisk/iCourse --redownload
```

此入口会重新开始该课次的临时下载；正式旧录像保留到新录像通过验证。不要用它代替普通网络中断后的续传。命令行凭据配置见前文。

为已有正常录像补笔记时，选择“下载录像并生成笔记”即可；会复用可用转录或进行云端转录，可能产生费用。普通运行不强制重做已有笔记。新下载始终按原规则验证完整性后才发布。
