# 常见问题

## 安装器提示系统不支持

本版需要 Apple Silicon M 系列、macOS 14.0+。在 Terminal 执行 `uname -m` 应显示 `arm64`。若 M 系列电脑显示 `x86_64`，检查 **Finder → Applications → Utilities → Terminal → Get Info**，关闭 **Open using Rosetta** 后重开 Terminal。Intel Mac 不支持此安装入口。

## uv / ffmpeg / ffprobe 找不到

在 Terminal 中执行 `brew install uv ffmpeg`，按 Homebrew 的提示完成 PATH 配置，再重开 Terminal。安装器和 App 都检查 Homebrew 常见安装位置。只安装 Python 不够；音视频解码还需要 ffmpeg 与 ffprobe。

## 语音服务连接或转录失败

0.5.0 起不下载本地语音模型。在设置中检查语音地址、完整模型名称和独立的语音 API Key。“检查语音连接”在兼容模式读取模型列表，在百炼模式检查上传凭证；不会上传音频或提交识别。

- HTTP 401 / 403：检查密钥、账号权限和模型访问权限。
- HTTP 400 / 404 / 422：检查地址和模型名；语言、术语与返回格式先保持默认，只有服务支持时才填写。
- HTTP 413：降低音频块时长或上传大小限制。
- HTTP 429 / 5xx：程序会有限重试；检查额度、限流或服务状态。
- 超时或停止：已保存的成功块保留；重新运行可续转，但服务端可能已经处理当前未完成请求，重试可能重复计费。
- 空文本：个别块未识别到文字时，原文标注时间段并继续；请对照录音检查，必要时更换模型。整节课均为空仍报错，不输出已完成转录。全数字静音块会跳过上传。

默认星辰的实测结果只有文字，不包含字幕时间戳；没有 SRT 是正常的。要字幕需选择支持真实时间戳的服务和返回格式。详见[云端转录说明](cloud-asr.md)。

**录像有讲话但整课识别为空：** 先升级到 0.5.2。某些录音左右声道极性相反，旧版混合为单声道时会将讲话抵消。新版检测到这种情况会保留有效声道并记录提示。正常运行即可重试失败课次，不需要重下视频；若仍为空，再对比已下载文件和网页回放的音轨、模型及录音质量。日志现在会逐块显示转录推进，不能仅从“空文本”推断录音没有声音。

## 外置磁盘或 Documents 没有访问权限

典型错误：`PermissionError: Operation not permitted: '/Volumes/…'`。这通常与 macOS 隐私权限有关，也可能是磁盘挂载、文件夹权限或连接问题。

1. 先在 Finder 确认磁盘或 Documents 中的目录存在，并能在目标目录新建一个普通文件夹。
2. 在 App 中点保存位置右侧“选择…”，重新选择目标文件夹。若系统询问访问权限，选择 **Allow**。
3. 打开 **System Settings → Privacy & Security → Files & Folders**。找到实际运行的 iCourse 条目并展开；若有 **Removable Volumes** 或 **Documents Folder**，开启对应权限。
4. 退出并重开 App，重试一个课次。命令行运行时，系统可能把访问权限归到 **Terminal**，应检查实际启动方式对应的条目。

没有出现 Allow 或 iCourse 条目时，不代表权限已经授予。先确认用的是 `~/Applications/iCourse.app`，完成安装后重新选择目录；可暂时选择用户文件夹下新建的 `~/iCourse` 目录来区分程序问题和受保护目录问题。

如果始终没有可用的授权项，可在 Finder 将原笔记根目录完整复制到用户文件夹下，例如 `~/iCourse/courses`，然后在 App 中把“笔记保存位置”改为这个新目录并保存设置。保留原目录直到确认新位置正常；完整复制可以带上既有转录和隐藏状态，避免重复调用 API。仅切换为空目录不会自动迁移旧笔记。

0.3.1 起，程序会在学校登录和模型任务前检查所需目录。“只下载录像”不使用笔记目录。权限检查和友好提示不能替代系统授权，也不能保证此前被拒绝的 App 会自动弹出新的 Allow 对话框。[Apple 的文件访问权限说明](https://support.apple.com/guide/mac-help/control-access-to-files-and-folders-on-mac-mchld5a35146/mac)。

**每次重开都要重新选目录：** 先升级到 0.3.2 或更新版本，并固定从 `~/Applications/iCourse.app` 打开。旧版使用脚本作为 App 主入口，会影响 macOS 对权限归属的识别；0.3.2 改为原生入口，并在 App 进程内检查目录。选择目录后点击“保存设置”，按系统提示授权一次，正常重开应继续使用原路径和已授予的权限。路径保存和系统授权是两回事：程序能保存路径，但不能代替用户授权。

本地构建 App 使用 ad-hoc 签名，重新构建、重新安装或系统权限被撤销后，仍可能需要再次授权。这与每次普通打开不同。自动化测试只验证连续启动的身份和设置恢复，真实 TCC 授权保留需要用户在系统提示中允许后验证。[Apple DTS 对原生入口及稳定签名身份的说明](https://developer.apple.com/forums/thread/678819)。

如果 Finder 自己也无法写入，先解决磁盘问题。扩展坞连接不稳、只读挂载、文件系统损坏不会被隐私权限开关修复。不要用 `chmod 777` 或给 Python 加 `sudo` 代替定位原因。

## 登录失败或找不到课程

先用浏览器验证自己的 UIS 登录和 iCourse 访问是否正常。课程 ID 与单节回放的课次 ID 不同；不要把回放 ID 填进课程 ID。新学期需要更新课程 ID。登录成功但“暂无回放”可能只是平台还没有发布，稍后手动重试。

“视频未到开放时间”是学校尚未开放这一课次；0.5.2 起标为等待开放，不计为下载失败，也不重复登录或立即重试。其他可用课程照常处理，下次正常运行再检查。

## 一直显示“生成笔记中”

这个计时表示还在等待模型回答，不表示字数进度。整节课一次生成可能需要几分钟；输入长度、服务负载和模型选择会影响等待时间。默认单次最长等待 20 分钟。

“超时”表示在指定时间内没有收到完整响应，客户端停止等待。服务端仍可能已处理请求，重试可能再次产生费用。查看之后是否出现明确错误或重试提示，不要同时启动多个相同任务。

## 摘要输出被截断

模型因输出预算不足或其他停止原因没有完整写完。程序不会把它标记完成，也不会自动分章继续请求。

先查看日志中的实际输出预算。如果只有 1024 tokens 等很小的值，在设置中点击“恢复笔记推荐参数（65536 tokens / 20 分钟）”并保存。0.5.1 起，原文达到 8000 字符且预算低于 4096 tokens 时会在调用前提示，避免浪费请求；滚动设置页面也不再改变数值或下拉选项。

在服务商支持范围内提高“单次输出上限”，或换成能够处理整课输入并输出足够内容的模型，然后用“下载录像并生成笔记”重试缺少笔记的课次。如果服务提示上下文过长，需要支持更长上下文的模型；程序不会悄悄删除原文。65536 是客户端默认预算，不代表所有模型都支持；不能保证所有服务、所有长度的课程永不失败。

## 已有课程的复用检查特别慢

0.5.0 及更早版本在每次进程启动后重新读取整段视频来校验内容，慢速 U 盘上的大视频可能需要数分钟。0.5.1 会将至少 8 MiB 文件的已验证哈希保存在 `~/Library/Caches/Fudan iCourse Subscriber/file-hashes/`。首次检查仍需完整读取；以后文件路径、设备、文件编号、大小和修改时间等信息不变时直接复用。缓存不含密钥或视频内容，删除后会自动重建。

视频移动、修改、磁盘重新挂载导致设备信息变化或缓存被清理时，可能重新完整校验。缓存不能检测文件信息完全未变的静默存储损坏；怀疑磁盘有问题时，在命令行设置 `ICOURSE_VERIFY_FILES=1` 再运行原命令，可强制在该进程首次访问时完整校验。

## 生成了笔记，但再次运行还想重新生成

普通运行复用已有正式笔记。带有完成记录的笔记允许手动修改正文，不会因移动目录或正文修改就重新调用模型。空文件、待核对记录仍需处理。需要强制重写时使用高级 CLI `run --mode summarize --redo-notes` 并限定课次；桌面只补缺项。旧笔记隐藏归档，新笔记成功提交才替换当前文件。

## 为什么还有 JSON / .icourse / 旧稿

新版本把校验与进度文件放到隐藏 `.icourse`。它们不是要手动配置的参数，也不含 API Key。旧版本可见的同名 JSON 会在处理对应文件时迁移；已确认属于程序的同课次待核对稿会在新笔记成功后归档。无法确认来源的文件不会自动删除。

## 命令行已更新，App 还是旧逻辑

App 运行独立安装的程序包。更新源码后，退出 App 并重新运行 **安装 Mac.command**，再打开 `~/Applications/iCourse.app`。单纯修改源码或运行 `git pull` 不会更新已安装的 App。

## eLearning 点击后提示填写账号，或独立窗口无法登录

从 `~/Applications/iCourse.app` 的主窗口进入 eLearning。在统一「设置」填写当前学号与密码，再手动点击刷新或同步。没有额外许可弹窗；也不要求另外创建 token。独立 `启动 eLearning.command` 仅供隔离界面测试，不连接统一设置。

缺少凭据时不会发起登录。401 表示需要重新认证，403 表示权限拒绝；验证码或二次认证会停止，当前没有人工挑战续接。可由用户亲自在学校网页确认账号可用，但程序不会借用浏览器 Cookie。不要把原始密码或响应正文附在故障报告中。

## eLearning 为什么没有下载老师更新的文件

当前规则为**同名就保留**。仅在该课程 `课件/` 及允许的子目录检查普通文件，安全名称经 NFC 和不区分大小写规范化后匹配。同名时不比较正文，即使大小或远端修改时间变化也不下载、不覆盖、不另存；本地批注始终保留。

这是成功跳过，不是确认本地与远端相同。没有同名比对勾选项，也不需要确认。查看最新同名资料须由用户在学校页面自行处理；程序不能根据跳过结果判断本地内容是否完整。异名内容去重仍可能临时下载完整文件，详细日志会如实说明传输量。

旧 `CLOUD/`、`课程ppt/`、`资料/` 中有文件，不会阻止同步到 `课件/`；它们不在查重范围。目标被目录、符号链接或其他非普通文件占用时会报错，程序不会绕过或覆盖它。

## eLearning 大小、短读与写入失败

| 现象 | 当前行为与处理 |
|---|---|
| 达到上限或缺少可靠大小 | 严格要求 `<50,000,000` 字节，等于上限也跳过；所有扩展名使用同一规则 |
| HTTP 200，但清单与实收长度不同 | 不发布残缺文件；确认短读或正文读取中断时最多从头尝试 3 次，等待 1 秒、2 秒 |
| 三次重试耗尽 | 保留已成功文件；检查网络后再次手动同步。失败计数与诊断不能定位具体服务器/代理/链路原因 |
| HTTP 401/403、异常跳转、学校登录表单 | 停止该认证或权限失败，不能把登录页面保存为课件；重新确认账号与课程访问权限 |
| 清单/响应大小不符、非完整响应或编码变化 | 拒绝发布，不进入短读重试；先核对学校源文件和响应，不放宽校验 |
| 保存失败或无法完整遍历课件目录 | 检查目录权限、磁盘空间和连接；不通过跳过目录检查继续写入 |

诊断仅输出必要的长度、状态和已过滤头字段，不需要提供签名下载链接。入口连接建立失败并不保证自动重试；这里的三次重试针对已经开始的正文传输。录像的 Range 续传与 eLearning 的整文件重试不同。

重跑会保留同名文件并复用可验证的异名重复文件，不因一个文件失败重传其他成功文件。不要删除课程或索引来“清缓存”。强制结束留下的 `.elearning-*.part` 不作为成功课件；如需清理，先确认没有任务在运行，再只处理确认属于中断下载的临时文件。

## 作业少了、截止日期不同或没有收到提醒

先手动刷新，检查是否有读取错误及当前筛选条件。内容锁定作业在所有界面筛选和普通日志中隐藏，已完成的锁定项也隐藏；基线仍保留，解锁后刷新可重现。原始 JSON/本地提醒历史可能仍含锁定项。

截止日期使用接口对当前学生生效的 `due_at`，北京时间展示；`lock_at` 是关闭访问时间，不等于提交截止时间。缺失日期或状态会显示未确认，不自行推断。

首次成功检查仅建基线；之后手动刷新/同步发现新增 ID 或截止日期变化才写入本地提醒。单纯提交状态变化不属于新增/延期提醒。没有启用后台轮询、临近截止提醒、邮件或系统通知；程序未运行时不会主动检查。

## 任务锁冲突、停止或更新失败

不要手动删除仍可能被使用的锁文件。先等待另一个录像/eLearning 进程结束；在 App 中停止并等待界面恢复，再正常退出。进程退出会释放系统锁，锁文件存在本身不代表仍有任务。

正式更新前必须退出 App 并停止独立 CLI。现有安装器只检查录像 `pipeline.lock`，尚未内建 eLearning `run.lock` 和空闲 App 检查。安装失败可在所有任务停止后重新运行安装器；不要先删除用户数据。原地更新尚无完整运行环境回滚，详见[架构评审](architecture.md)。

## App 打不开或没有错误窗口

用 Finder 的 **Go to Folder…** 打开 `~/Library/Logs/Fudan iCourse Subscriber/`，查看 `application.log` 的末尾。运行安装器可检查 Python、依赖与 App 是否完整。

提交 Issue 时提供 macOS 版本、芯片、程序版本、失败阶段和去除敏感信息的错误片段。日志可能含课程标题、路径或带参数的播放链接；不要上传完整日志、`.env`、设置文件、钥匙串凭据或课程内容。

### 启动后长时间“读取课程”，但没有开始下载

默认在线任务现在按已有录像文件名快速跳过，不再因为设备编号变化重新计算旧视频 SHA-256。状态“已有，未校验／跳过”不代表录像完好；遇到已知异常记录仍会显示失败。需要核对某节录像时使用“完整校验录像…”并指定课次，不必重下或转写。

如果曾出现零内容校验文件或磁盘不可读，先保留现场、备份可读数据并排查存储连接；不要通过删除异常记录或禁用新下载验证来获得“成功”。手动校验会完整读取选择的录像，疑似故障介质上应先处理存储风险。

### 外置盘写入后回读不一致（0.6.7）

录像和临时下载直接保存在选定的外置盘，内置盘只保存少量接收摘要。此错误表示回读字节未匹配下载时记录的摘要，或校验 JSON 写入后无法原样读取；程序暂停本轮后续下载，并保留临时文件、本机摘要及失败原因，不再连续整课重下。它能发现异常，不能自行修复磁盘、控制器或文件系统。

先检查连接和存储可靠性，保留可读数据。之后只选择一个课次，点击“重新下载指定录像…”，验证后再扩大范围。此操作保留已有原文和笔记。普通网络中断仍用“仅重试失败课次”，已有可信分段会先回读再续传。

若显示“下载数据与回读一致，但媒体检查失败”，接收内容已通过本地比较，但媒体工具仍无法解析；诊断会带退出码和脱敏原因。保留的临时录像可用于排查学校源文件与传输内容。该课本轮不再自动下载三次，其他课次可以继续。

### FAT/exFAT 外置盘出现 `._` 开头的同名文件（0.6.8）

macOS 可能在外置盘上为录像、原文和笔记生成 `._` 开头的辅助文件。它们不是另一份课程内容；0.6.8 在课次扫描、完整校验及旧目录迁移时忽略这些文件，保留辅助文件本身，避免假重复、误选录像或误跳过尚未生成的笔记。
