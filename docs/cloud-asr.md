# 云端语音转录

0.5.0 起不再提供本地语音识别。Mac 使用 ffmpeg 提取、压缩音频，发送到你配置的语音服务。取得各块文字后，合并整节课原文，再交给笔记模型一次总结。语音分块不会引入提纲、分章写作或额外笔记核对调用。

## 阿里云百炼（Fun-ASR / Paraformer）

App 按接口协议调用模型，不按模型名判断能力。0.6.2 起百炼模型字段可以自由输入；下拉框只是常用示例，不是支持名单。服务端仍需支持该模型、所选地域和账号权限，并返回程序能够解析的带时间戳结果。

1. 在 App 的“设置 → 语音服务”选择“百炼录音文件接口（异步识别）”。
2. 北京地域地址保留 `https://dashscope.aliyuncs.com/api/v1`，也可填写业务空间的 `https://<WorkspaceId>.cn-beijing.maas.aliyuncs.com/api/v1`。
3. “百炼语音模型”直接输入服务商文档中的完整模型 ID，也可选示例 `fun-asr` 或 `paraformer-v2`。保留大小写、斜杠、日期版本等字符，不填产品展示标题。输入框不在下拉列表中的值也会保存并发送。
4. “百炼 API Key”填写北京地域的百炼密钥。密钥与兼容服务分开保存在系统钥匙串，切换服务不会互相覆盖或转发。
5. 语言通常留空自动识别；需要指定时填模型支持的语言代码。支持多语种提示的模型可用英文逗号分隔，数量限制以模型文档为准。“时间戳校准”默认不发送额外参数；确认模型支持 `timestamp_alignment_enabled` 后，才选择开启或关闭。此开关与是否输出字幕不同：字幕使用服务实际返回的起止时间。
6. 保存设置，点击“检查语音连接”。检查只获取模型上传凭证，不上传音频、不提交付费识别；实际识别权限和效果仍需短录音确认。

已保存的配置会在重启后恢复。0.6.2 不再按模型名称自动切换接口；用户明确选择的接口会保留。非常旧的配置如果没有接口类型，且地址明确是百炼原生 `/api/v1`，才按地址迁移，模型原样保留。`/compatible-mode/v1` 不会被猜测为原生接口；需要在界面明确选择。独立配置的不同百炼密钥不会被覆盖。

旧课补字幕：选择“为本地课程生成笔记”，指定课程 ID 和一个课次，勾选“重新生成已有转录和笔记”。已有 MP4 会复用，新转录完成后在录像旁保存同名 SRT。“只重新生成笔记”不会重新转录或补字幕。重新打开视频或重新载入字幕后可在 IINA 查看。

默认每五分钟上传一块，合并时间轴时加回该块在整课的位置。长句只有在词时间戳有效且文字匹配时才拆成短字幕，不按字数均分出假时间戳。完整文字合并后仍只发一次正常笔记请求。

### 更换模型或服务地址

同一协议下，修改地址、完整模型 ID 和该服务的 Key 即可，不需要修改源码。例如官方录音接口文档还列出了 `fun-asr-2025-11-07` 和 `qwen-audio-3.0-asr-flash-filetrans`；可以按服务商文档输入这些名称，但它们未在本项目完成真实音频验收。[官方模型与协议说明](https://help.aliyun.com/zh/model-studio/fun-asr-recorded-speech-recognition-http-api)

“百炼录音文件接口”要求服务实现上传凭证 `/uploads`、提交 `/services/audio/asr/transcription`、查询 `/tasks/{task_id}`，以及 `transcripts[].sentences[]` 的毫秒起止时间。自定义 HTTPS 网关也可以填写，但必须兼容上述完整流程。文件上传和结果下载只接受配置地址的同源地址或阿里云 HTTPS 存储地址，API Key 不发送到存储服务器。

“OpenAI 兼容音频接口”使用 `/audio/transcriptions` 上传文件。聊天、实时 WebSocket 或其他结果结构的接口需要单独适配，不能仅凭“模型名称里带 ASR”判断兼容。

模型、地址和时间戳校准选项会影响块缓存。0.6.2 的百炼缓存加入校准选项，未完成的旧百炼任务应先用旧版本完成，避免更新后重新识别已处理的块。已有整课 TXT、笔记、MP4 与 SRT 不会因升级自动重做；要换模型处理旧课，需要明确选择“重新生成已有转录和笔记”。

### 上传与恢复

桌面版使用百炼官方私有临时存储，不需要额外填写 OSS AccessKey。音频对象使用随机文件名，临时地址有效 48 小时。厂商将此上传方式定位为开发测试使用，不适用于生产服务或大规模并发部署；此类部署需另接自有 OSS。[官方临时文件说明](https://help.aliyun.com/zh/model-studio/get-temporary-file-url/)

上传凭证、签名 URL 和 API Key 不写进任务缓存或日志。API Key 仅发送到百炼 API；文件存储使用临时上传凭证，下载结果不携带 API Key。

每块提交成功后立即保存任务编号。停止客户端不会撤销云端任务；再次运行优先查询原任务。查询暂时失败会有限重试；等待超时保留编号，下次继续查询。获取结果后先缓存结果，再由主进程保存完成块，避免两者之间中断后重复识别。

如果总在同一个音频块失败，先查看该行的具体错误码。0.6.4 起会从任务及音频子任务结果中提取错误码，并将任务编号等最小诊断资料保留到私有转录缓存的 `*.task.failure.json`；不保存原始服务消息、音频链接或 API Key。重试成功后会清理对应失败记录。可用“复制问题摘要”提供显示出来的错误码，无需提供密钥。

旧版“任务失败或已取消，请核对模型权限、余额和音频格式”是统一提示，不能据此认定余额不足、模型不可用或音频损坏。阿里云的[任务查询接口](https://help.aliyun.com/zh/model-studio/fun-asr-recorded-speech-recognition-http-api)会通过 `code` 和 `message` 返回更具体的原因。失败后无需清空整个课程缓存；成功音频块会复用，只有确认失败的块需要重新提交，可能再次计费。

`ASR_RESPONSE_HAVE_NO_WORDS` 表示最终识别结果为空，`SUCCESS_WITH_NO_VALID_FRAGMENT` 表示服务未检测到有效语音，参见[官方错误码说明](https://www.alibabacloud.com/help/zh/model-studio/error-code)。这不等于原录音绝对没有讲话。0.6.5 起会将这两类明确结果作为空识别块缓存，在原始 TXT 和日志标注时间段后继续，不为该段编造文字或字幕；后面的字幕仍按原时间轴排列。如果整节课都没有识别文字，任务仍失败，不生成空笔记。

遇到这两个错误后可直接重试：前面成功块保持复用；0.6.4 已保留的空识别失败记录在编码音频、语音配置与时长完全匹配时也会复用，不重复上传。若该段实际有重要讲话，需要对照原录像，必要时单独截取该段换模型识别；继续处理不会补回缺失内容。其他错误（下载、解码、鉴权、余额、取消或不明错误）不会按空识别跳过。

提交请求发出但没有收到编号时，无法确定是否计费，因此不自动重复提交。请先在百炼核对，再清理对应缓存后重新运行；重新提交可能再次计费。云端结果下载地址仅有效 24 小时，过期且本机尚未保存结果的任务可能需要重新识别。

恢复信息与块缓存在 `~/Library/Application Support/Fudan iCourse Subscriber/asr-cache/`。更换模型会使用独立缓存，不把 Fun-ASR 的文字当作 Paraformer 的结果复用。

### CLI 配置

在自己的 `.env` 中设置以下选项，并填写 `ASR_API_KEY`（不要在命令历史中输入密钥）：

```dotenv
ASR_PROVIDER=dashscope
ASR_BASE_URL=https://dashscope.aliyuncs.com/api/v1
ASR_MODEL=fun-asr
ASR_API_KEY=
ASR_LANGUAGE=
ASR_TIMESTAMP_ALIGNMENT=default
ASR_INITIAL_PROMPT=
ASR_RESPONSE_FORMAT=
```

换模型时，将 `ASR_MODEL` 改成服务商给出的完整 ID。`ASR_TIMESTAMP_ALIGNMENT` 可选 `default`、`enabled`、`disabled`，默认不发送该可选参数。

```sh
icourse check-asr --env-file .env
icourse transcribe --env-file .env /path/to/audio.mp3
# 覆盖模型与校准选项（Key 仍从配置读取，不放入命令行）
icourse check-asr --env-file .env --model paraformer-v2 --timestamp-alignment enabled
```

### 连接检查失败怎么办

| 提示或现象 | 处理方法 |
|---|---|
| “服务未提供兼容的模型列表” | 核对“语音服务”；百炼原生录音地址必须选择百炼接口，不能用兼容接口检查 |
| “模型列表中未找到所填模型” | 兼容接口返回的列表没有该 ID；核对完整名称及账号权限，列表不一定涵盖全部语音模型 |
| “不能使用 /compatible-mode/v1” | 原生百炼模式的地址应为 `/api/v1` 或服务商指定的原生基础地址 |
| HTTP 401 / 403 | 核对当前服务的 Key、地域、模型权限和余额；语音 Key 与笔记 Key 是两个字段 |
| 连接成功但转录失败 | 连接检查不上传音频；先用一个短录音验证模型、时长限制与返回格式 |
| 下拉菜单里没有想用的模型 | 直接在模型框内输入完整 ID；不必等待程序更新示例列表 |

更新程序后按 **⌘Q** 完全退出，再打开 iCourse；模型输入框应允许编辑。保存后可再次重开确认配置恢复。

验证范围：离线 HTTP 模拟覆盖两种模型的上传、提交、查询、时间戳解析、跨块偏移、恢复与密钥隔离；两种模型均已用同一段 45 秒课堂录音完成真实端到端转录与 SRT 输出验证。专业术语仍可能识别错误，短样本结果不能代表整课准确率。先用一小段录音确认账户、地域、识别文字和字幕同步，再批量处理。

接口依据：[Fun-ASR 录音识别](https://help.aliyun.com/zh/model-studio/fun-asr-recorded-speech-recognition-http-api)、[Paraformer 录音识别](https://help.aliyun.com/zh/model-studio/paraformer-recorded-speech-recognition-restful-api)。

## 兼容语音服务配置

在“设置”填写以下字段，点击“保存设置”：

| 字段 | 硅基流动默认配置 |
|---|---|
| 语音服务地址 | `https://api.siliconflow.cn/v1` |
| 语音模型 | `XingChenAGI/XingChenASR-V3.2-Ultra` |
| 语音服务 API Key | 你自己的硅基流动 API Key |
| 语音语言、专业术语 | 留空 |
| 语音返回格式 | 服务默认 |
| 音频块最长时长 | 300 秒 |
| 单次上传大小上限 | 20 MB |
| 语音请求等待上限 | 300 秒 |
| 语音请求重试次数 | 2 次 |

点击“检查语音连接”会查询 `/models`，不上传音频。部分兼容服务没有模型列表，此检查失败不一定表示转录不可用，需按照服务文档核对配置后试一个短文件。

语音密钥与笔记密钥分别存入系统钥匙串；服务地址和模型保存在普通设置中。只下载、复用旧转录重写笔记时不需要调用语音服务。

## 换模型与服务

同一个服务更换语音模型时，修改“语音模型”为该服务的完整模型 ID。已有课程需要改用新模型时，勾选“重新生成已有转录和笔记”；普通任务继续复用已完成的课程文件。更换服务时同时修改地址、模型和密钥。不要把聊天模型名称填入语音模型。

当前实现支持 **OpenAI 兼容的音频文件上传协议**：`POST <基础地址>/audio/transcriptions`，Bearer 认证，multipart `file` 和 `model`。也可填写完整的 `/audio/transcriptions` 地址，程序会自动规范化。无需在代码中添加模型白名单。

语言、术语、返回格式仅在非空时发送。不同模型支持的参数不同；不要向不支持的接口强行要求 `verbose_json`。支持标准时间戳响应的服务可以选择它生成字幕。例如 Groq 的兼容基础地址为 `https://api.groq.com/openai/v1`，模型和限制以其文档为准；本版没有对该服务做真实音频验收。

Fun-ASR / Paraformer 的异步录音识别使用上面的百炼模式，不能仅在兼容模式中改地址。WebSocket 实时识别等其他协议仍需另行适配。兼容音频上传协议与“任意语音 API”不同。

参考：[硅基流动音频接口](https://docs.siliconflow.cn/docs/api/audio-transcriptions-post)、[Groq 语音接口](https://console.groq.com/docs/speech-to-text)。新模型限制可能不同于通用文档，以上默认值是客户端选择，不代表厂商保证的最大限额。价格、额度与限流以服务账户为准。

## 长课、恢复与字幕

音频先解码为 16 kHz PCM 并保留原始声道。0.5.2 会在分布于整课的多个短片段中检查左右声道抵消；遇到反相录音时使用有效声道，避免原录像能听见讲话、混合后却近乎无声。普通立体声仍混合两边内容。此检测针对双声道，并不替代人工音质检查。

得到单声道 PCM 后，每小时约占 115 MB 临时空间；立体声转换时两份 PCM 短暂共存，峰值约每小时 345 MB，转换完成即删除多声道中间文件。不会将整课加载到内存。每次仅压缩一块为 64 kbps MP3，五分钟约 2.4 MB。程序会按时长和大小限制取较小值，尽量在末尾八秒内的安静位置切分；没有停顿时按最长时长切分，极少数边界词仍可能影响识别。

成功的块保存在 `~/Library/Application Support/Fudan iCourse Subscriber/asr-cache/`，只保存文字、时间戳和校验信息，不保存密钥或上传音频。它包含课程文字，不应公开分享。任务结束或正常取消后清理临时音频。异常断电可能遗留系统临时文件。

缓存按源文件内容和语音配置区分。再次运行会验证并复用成功块，不需要重新上传整节课。修改地址、模型、语言、提示词、格式或分块设置会使用新缓存；只更换密钥或重试预算不会重做已成功内容。“重新生成已有转录和笔记”仍可复用这些块；如需同模型重新请求全部音频，可在停止任务后通过 Finder 删除 `asr-cache` 中对应缓存，或清空该目录（其他课程以后也需要重新请求）。

0.5.2 的音频处理方式发生变化，需重新转录的课次会使用新的块缓存；已完成的整课 TXT 和笔记不会因此强制重做。

401、403、无效模型和参数等错误不会重复请求；连接失败、超时、429 及部分临时服务错误会有限重试。已成功块不会重传；未收到完整响应的当前块无法确认服务端是否完成，重试可能重复计费。停止客户端也不能保证撤销服务端计费。

0.5.1 起，格式有效但文字为空的响应不会中断整课。程序会在原文中标记“该时间段未识别到文字”，继续后面的音频，并在完成时提醒有多少段需对照录像。这不能证明该时段没有讲话，也不会补写猜测内容。只要整课识别到部分文字，空块与非空块一起缓存；如需重新识别这些时段，可换模型或按上述方法清理对应缓存。整课全部为空时仍报错，不输出已完成转录，并删除空块检查点，供下次重试。

星辰 Ultra 的本版五分钟实测响应为 `text`、`duration` 和 `usage`，没有时间戳。这样的结果会生成完整 TXT 和后续笔记，**不生成虚假的 SRT**。如果每个有文字的块都返回有效时间戳，程序才合并输出字幕。重新转录时若无法生成新字幕，旧 SRT 会移入旁边隐藏的 `.icourse`，避免播放器继续加载旧字幕。

原来用本地模型生成的 TXT、笔记和字幕可继续使用；普通任务不会强制重转所有历史课程。旧本地模型缓存可能与其他软件共用，升级不会自动删除它们。
